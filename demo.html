The Problem
Why Current Learning Is Fundamentally Broken
Two dominant paradigms, both deeply flawed

❌ Passive Video Courses (Coursera, Udemy)

  • • One-size-fits-all rigid lectures that can't adapt to your background
  • • 5-10% completion rates — passive watching kills retention
  • • Outdated the moment library APIs change
  • • Zero context about YOU — your pace, your gaps, your style
  • • Locked inside proprietary cloud platforms

❌ Amnesic AI Chat (ChatGPT, Claude, Gemini)

  • • Forgets everything after a few turns — total context amnesia
  • • Dumps 500-word walls of unverified text — illusion of learning
  • • No curriculum, no milestones, no proof of what you actually learned
  • • No persistent state — each session starts from scratch
  • • Zero integration with your actual workspace or code
The Paradigm Shift
Context-Based Learning: Built Like Software
Software projects have git history, state files, CI pipelines, and per-developer context. Why doesn't learning?

✅ The TextCourses Thesis

Every single interaction a learner has is recorded, contextualized, and used to build an extraordinary, personalized learning experience.

  • → Context accumulates — like git commits. Every concept taught, every question asked, every misconception identified is permanently logged.
  • → State persists — like project config files. Your progress, preferences, strengths, and weaknesses are tracked in structured data files.
  • → Quality is verified — like CI pipelines. Courses are stress-tested through adversarial debate before you see them. Your understanding is probed through diagnostic scenarios.
  • → Experience adapts — like feature flags. The teaching style, depth, pace, and even the AI teacher persona morphs based on YOUR accumulated context.

🔧 The Skills Framework = The Build System

The 10 TextCourses skills (/tc-init, /tc-research, /tc-create, /tc-teach, etc.) are the intermediate build pipeline — like webpack or cargo — that transforms raw knowledge into structured, verified, personalized learning experiences.

Each skill handles one specific phase of the pipeline. Together, they produce courses that get posted to textcourses.com as the end-user product.

⚡ Stage 1: Onboarding & Learner Profile (/tc-init)

Zero-friction, turn-by-turn intake. One question per turn — never cognitive overload.

  • → Captures: Role (10 options), Experience Level, Explanation Density, Preferred Teacher
  • → Scans existing workspace for active courses and unfinished sections
  • → Recommends the single best next action deterministically
  • → Profile evolves at chapter boundaries based on interaction patterns

Context captured: profile/preferences.md, profile/memlog.md

🔬 Stage 2: Autonomous 5-Hat Research (/tc-research)

Marie Curie leads multi-round autonomous research with 5 critical perspectives.

🛠️ Stage 3: Triad Consensus Course Creation (/tc-create)

Never stalls asking "how do you want this course?". Autonomously builds and debates.

  • → Brainstorms 4 distinct curriculum paths (First-Principles, Project-First, Problem-Driven, Metaphor-First)
  • → Adversarial Triad Debate: Daedalus (Architect) proposes, Marie (Scout) fact-checks, Hypatia (Auditor) catches cognitive leaps
  • → Course cannot be created if any Triad member dissents
  • → Scaffolds chapters, sections, concept checklists, and practical specs
  • → Also supports 5 Universal Curriculum Archetypes (Applied Creation, Forensic Dilemma, Axiomatic Primitives, Spiral Immersion, Reverse Engineering)

🦉 Stage 4: Socratic Teaching & Adaptive Fork (/tc-teach)

The core learning loop. One concept at a time. Zero jargon leakage. Full context tracking.

  • → Delivers exactly ONE concept per turn with physical analogy + worked example + fatal anti-pattern
  • → Atomically toggles - [ ] to - [x] in lesson-plan.md (survives interruptions)
  • → Logs every turn to session.jsonl — persistent across sessions
  • → Every turn ends with Next-Action Fork: [1] Next [2] Test Me [3] Re-explain [4] Custom
  • → Detects repeated friction → offers adaptive teacher handoff (e.g., Turing→Feynman)
  • → Auto-compiles permanent textbook notes.md on section completion
// session.jsonl — every turn is tracked {"turn":1,"concept":"mutex_intro", "teacher":"Hypatia", "learner_input":"next", "friction_count":0} {"turn":2,"concept":"deadlock_scenarios", "teacher":"Hypatia", "learner_input":"re-explain", "friction_count":1} {"turn":3,"concept":"deadlock_scenarios", "teacher":"Feynman", "learner_input":"next", "handoff":"Hypatia→Feynman", "breakthrough":true}

🛠️ Stage 5: In-Loop Practical Labs (/tc-practicals)

Real code challenges evaluated by AI against 5 invariants. No faking competence.

  • → Daedalus scaffolds practical.md with functional requirements + boundary constraints
  • → Learner writes genuine code in their workspace
  • → AI evaluates: Syntax, Boundary Conditions, Defensive Guards, Error Safety, Idiomatic Craft
  • → PASS verdict required before section can lock as complete
  • → If test-ledger.jsonl shows recurring misconceptions, practical exercises target those weak areas
// practical-result.json — per evaluation { "verdict": "PASS", "score": 87, "rubric": { "syntax": "pass", "boundary_checks": "pass", "defensive_guards": "pass", "error_safety": "warn", "idiomatic_craft": "pass" }, "feedback": "Consider adding explicit fsync error handling..." }

📐 Stage 6: Diagnostic Testing & Mastery Ledger (/tc-test-me)

100% question-based. Zero code pasting. Tests deep mental models, not surface recall.

  • → Alan Turing poses Bloom's Taxonomy scenario dilemmas (Comprehension → Analysis → Evaluation)
  • → Diagnoses specific misconceptions and tags them for future retesting
  • → Records to tamper-evident ledger.toml with timestamps and scores
  • → Cumulative Boundary Rule: NEVER tests concepts from future sections
  • → Misconception data feeds back into practicals and future teaching
// ledger.toml — tamper-evident proof [[assessments]] timestamp = "2026-11-01T14:23:00Z" section = "ch01-sec02" bloom_level = "analysis" question = "Under what locking order is deadlock impossible?" outcome = "mastered" score = 0.92 // Misconception tracking feeds back misconception = "CONFUSION_LOCK_ORDER" remediation = "Retested in ch02 practical"
The Secret Weapon
The Context Accumulation Engine
This is what makes TextCourses fundamentally different from everything else. Every interaction builds a richer context graph that powers increasingly personalized experiences.

🧠 Dual-Register Memory

Human-First Notes (notes.md) — permanent, plain-English textbook written for the learner. Locked on disk once compiled. Yours forever.

AI-First Memory (memlog.md, session.jsonl) — ultra-dense, token-minimal telemetry. Feeds the AI exactly what happened without blowing up context windows.

🔄 Feedback Loops

Misconceptions from /tc-test-me feed into /tc-practicals to target weak areas. Friction patterns in /tc-teach trigger adaptive teacher handoffs. Style profiles evolve at chapter boundaries.

The more you learn, the better it teaches.

📦 Portable & Sovereign

All context lives in plain files: Markdown, TOML, JSONL, SQLite. Zero cloud databases. Zero vendor lock-in. Git-trackable. Transferable between machines. You own your learning data.

Decision Required — UX Direction
What Will Users Experience on textcourses.com?
The skills engine is the intermediate build system. But what is the end-user surface? Here are the viable directions — each with different trade-offs.

Core Decision: What Is textcourses.com?

The skills framework runs locally in AI coding agents today. But textcourses.com is a domain — it implies a web presence. The fundamental question is: Does the web surface host the learning itself, or serve as a catalog/community layer over local learning?

Ambitious

🌐 Option A: Full Web Learning Platform

textcourses.com IS the learning experience. Users sign up, select a course, and learn in a web-based chat/workspace interface powered by the skills engine on the backend.

✅ PROS

  • + Lowest friction — anyone with a browser can start learning instantly
  • + Full control over the UX/UI experience
  • + Context engine runs server-side — richer analytics and personalization
  • + Direct monetization path (freemium, subscription)
  • + Social features possible (leaderboards, cohorts)

⚠️ CONS / TRADE-OFFS

  • − Major infrastructure investment (servers, auth, databases)
  • − Contradicts "sovereign local-first" philosophy
  • − AI API costs scale with users
  • − Competing with established platforms (Coursera, etc.)
// Option A — User Flow User → visits textcourses.com → Sign Up / Login → Select Topic ("Distributed Systems") → Web Chat UI runs /tc-init intake in browser → Backend executes skills engine (tc-research, tc-create) → Web Chat UI delivers Socratic lessons (/tc-teach) → Progress Dashboard shows context graph, milestones → Notes & Portfolio downloadable as local files or git repo
Recommended — MVP

📚 Option B: Course Catalog + Local Skills Engine

textcourses.com is a beautiful course catalog and marketing site. Users browse topics, then install the skills into their local AI agent to learn. The website sells the vision; the local engine delivers it.

✅ PROS

  • + Zero infrastructure cost — static site (Astro/Next.js)
  • + Preserves sovereign local-first philosophy perfectly
  • + Users bring their own AI (OpenAI, Anthropic, local models)
  • + Open-source community can contribute course blueprints
  • + Fast to ship — website is just marketing + docs

⚠️ CONS / TRADE-OFFS

  • − Higher friction — requires local setup (AI agent + uv)
  • − Limits audience to developers & technical users
  • − Harder to monetize directly
  • − No centralized analytics on learning outcomes
// Option B — User Flow User → visits textcourses.com → Browses course catalog → Sees: "Distributed Systems", "Rust Internals", "Data Science" → Clicks "Start Learning" → Gets install command: npx skills add textcourses/distributed-systems → Opens their AI agent (Cursor, Claude Code, Antigravity, etc.) → Types /tc-init → learns locally with full sovereignty → Progress lives in their git repo → Optionally publishes portfolio to textcourses.com community
Best of Both Worlds

🔀 Option C: Hybrid Progressive Platform

textcourses.com offers a lightweight web learning experience (no local setup required) AND supports power users who want to run locally. Web users get a streamlined UI; power users get full sovereignty. Context syncs optionally.

✅ PROS

  • + Captures both casual learners AND power users
  • + "Try in browser, graduate to local" funnel
  • + Optional context sync between web ↔ local
  • + Multiple monetization paths

⚠️ CONS / TRADE-OFFS

  • − Most complex to build — two surfaces to maintain
  • − Context sync between web and local is non-trivial
  • − Risk of diluting the core value proposition
// Option C — Dual-Surface Flow Casual User Path (Zero Setup): textcourses.com → Click "Learn Now" → Web chat UI → Socratic lessons in browser → Progress saved to cloud account → Export to local git repo anytime Power User Path (Full Sovereignty): textcourses.com → Click "Install Locally" → npx skills add textcourses/... → Local AI agent → Full filesystem control → Optional sync to web dashboard Context Bridge: Web progress ←→ Local files via tc-sync command Export: web → git repo | Import: git repo → web dashboard
Long-Term Vision

🏛️ Option D: Community Blueprint Registry

textcourses.com becomes the "npm registry" for learning blueprints. Expert educators and engineers publish vetted course blueprints (roadmaps, curricula, research dossiers). Users install and learn locally. Community upvotes and reviews quality.

✅ PROS

  • + Network effects — community creates content
  • + Expert-curated blueprints add massive value
  • + Verifiable proof-of-work portfolios publishable
  • + Could become the standard for AI-assisted education

⚠️ CONS / TRADE-OFFS

  • − Requires critical mass of contributors to be valuable
  • − Quality control and moderation overhead
  • − Chicken-and-egg problem: needs users to attract authors
// Option D — Registry Flow Blueprint Author (Expert/Educator): Creates curriculum → tc-create + tc-research + tc-verify → Publishes to textcourses.com registry → Community reviews, upvotes, forks Learner: Browses textcourses.com → Finds "Canonical Raft Blueprint" (★ 4.8) → npx skills add textcourses/raft-canonical → Learns locally with full context engine → Publishes signed completion certificate to profile Monetization: Free blueprints (community) + Premium blueprints (expert-authored) + Enterprise team licenses (onboarding standardization)

Currently, personas are text-based identities in skill prompts. For a web experience, they could become:

Decisions Required
Key Product Decisions That Shape textcourses.com
These are the strategic forks that need your decision before building the user-facing product.

Decision 1: Primary Surface — Web vs Local vs Hybrid?

See UX Direction options above. This is THE foundational decision. Everything else cascades from it.

Recommendation: Start with Option B (Catalog + Local) as MVP. Evolve to Option C (Hybrid) as the product matures and demand validates web learning. Option D (Registry) is the long-term north star from the PRD vision.

Decision 2: Monetization Model

How does textcourses.com generate revenue?

💰 Freemium SaaS

Free basic courses. Paid premium content, advanced personas, priority AI, team features.

🏪 Marketplace

Expert educators publish paid blueprints. TextCourses takes a platform cut (like Gumroad/Udemy).

🏢 Enterprise Licenses

Companies pay for standardized onboarding tracks with progress dashboards and team analytics.

Decision 3: Target Audience Scope

The current engine is heavily technical (code, systems, engineering). Should textcourses.com expand to non-technical domains?

🎯 Technical Only (Current)

Software engineering, data science, systems, DevOps. Strong moat. Clear audience. The practicals and code evaluation features are differentiators.

🌍 Domain-Agnostic (Expansion)

Finance, medicine, law, languages, music theory. The PRD already calls out "domain-agnostic." The 5 curriculum archetypes are universal. But practicals and code eval become irrelevant.

Decision 4: Content Creation Model

Who creates the courses that users learn from on textcourses.com?

🤖 AI-Generated (Current)

The skills engine autonomously researches and creates courses per user. Every course is unique. Scalable but quality varies.

👩‍🏫 Expert-Authored

Domain experts use the skills as authoring tools to create vetted, curated blueprints. Higher quality, but doesn't scale.

🔀 Hybrid Seeded

Experts author blueprints as templates. The AI personalizes delivery per user's context, style, and pace. Best of both.

Decision 5: Context Data — Where Does It Live?

The context accumulation engine is the core differentiator. But for a web platform, where does learner context data live?

💻 100% Local

All files on learner's machine. Maximum sovereignty. Zero cloud dependency. Current model.

☁️ Cloud-First

Server-side storage. Enables web UI, cross-device access, analytics. Contradicts sovereignty.

🔄 Local-First + Optional Sync

Local is primary. Optional encrypted sync to cloud for backup, cross-device, and web access. User controls what syncs.

Decision 6: Proof of Learning — Certificates & Portfolios

How do learners prove what they learned?

📜 Signed Certificates

Cryptographically signed completion certificates verified against the tamper-evident ledger. Publishable to LinkedIn, GitHub, textcourses.com profile.

💼 Portfolio Artifacts

Real code projects from /tc-practicals with 4-lens AI review reports. Genuine proof-of-work, not just a badge. Publishable as git repos.
